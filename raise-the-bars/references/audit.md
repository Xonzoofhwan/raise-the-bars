# 일괄 진단 — 기존 문구를 한꺼번에 점검할 때

문구 하나를 쓰거나 고치는 것이 아니라, **이미 제품에 들어가 있는 문구
수십~수백 개를 받아 문제를 찾아내는** 모드다.

## 왜 이 모드가 있나

스켈터랩스·구름·라포랩스 **세 팀이 독립적으로 같은 단계를 밟았다** —
가이드라인을 만들기 전에 전체 문구를 한곳에 모아 점검하는 것이다.
라포랩스는 이 과정에서 *"그동안 암묵적으로 지키던 원칙이 수면 위로 드러났다"*고
진술했다.

즉 이 모드의 산출물은 **고친 문구 목록**만이 아니다.
**제품이 실제로 어떤 규칙을 따르고 있었는지**가 함께 드러난다.
그래서 **프로파일이 아직 없는 제품이라면** 이 모드를 먼저 돌리는 편이 낫다.
(이미 있으면 역추정하지 않는다 — 아래 0단계.)

## 검수 모드와 무엇이 다른가

| | 검수 (기본) | 일괄 진단 |
|---|---|---|
| 입력 | 문구 1~몇 개 | 문구 수십~수백 개 |
| 관심사 | 이 문구가 규칙을 지키는가 | **문구들 사이가 어긋나는가** |
| 산출물 | 수정 전/후 | 패턴 목록 + 우선순위 + 역추정한 프로파일 |
| 놓치면 안 되는 것 | 규칙 위반 | **일관성 붕괴** |

**핵심 차이는 이것이다 — 개별 문구는 다 멀쩡한데 모아놓으면 틀린 경우가 있다.**
"저장했어요"와 "저장되었습니다"는 각각 보면 문제가 없지만 한 제품에 같이 있으면
R-001 위반이다. 검수 모드로 하나씩 보면 절대 안 잡힌다.

---

## 절차

### 0단계 · 프로파일이 이미 있는가

**이 모드에도 SKILL.md 0단계의 프로파일이 그대로 걸린다.** 파일을 찾아볼 수
있는 환경이면 프로젝트 루트와 `docs/`의 `voice-profile.md`가 그 자리다.

- **있으면 읽는다.** 이미 정해진 프로파일이 있는데 역추정할 이유가 없다.
  이때 5단계는 역추정이 아니라 **대조**가 된다 — 실제 문구가 파일의 값과
  어긋나는지 보는 것이 산출물이다
- **없을 때만 역추정한다** (5단계). 이 모드에서는 세 질문을 묻지 않는다 —
  받은 문구가 이미 답을 담고 있기 때문이다

⚠ 이름이 다른 보이스 문서(`brand-voice.md` 등)를 대신 썼으면 **무엇을
프로파일 대신 썼는지 밝힌다.** 밝히지 않으면 사용자는 자기 제품의 프로파일이
반영된 줄 안다. → `profile.md`

### 1단계 · 무엇을 받았는지 정리

받은 문구를 **화면·기능별로 묶는다.** 사용자가 정리해 주지 않았으면 네가 묶는다.
파일에서 추출한 것이면 경로나 키 이름이 힌트가 된다.

문구가 100개를 넘으면 **한 번에 다 보려 하지 말고 묶음별로 처리한다.**
전체를 훑고 나서 심각한 묶음부터 자세히 본다.

### 2단계 · 일관성부터 본다 — 규칙 위반보다 먼저

개별 위반은 나중이다. 먼저 **어긋남**을 찾는다.

| 무엇을 보나 | 어긋남의 예 | 걸리는 규칙 |
|---|---|---|
| **종결 체계** | "저장했어요" ↔ "저장되었습니다"가 한 제품에 공존 | R-001 |
| **같은 액션의 어휘** | 어떤 화면은 '삭제', 어떤 화면은 '지우기', 또 어디는 '제거' | R-001, R-011 |
| **같은 대상의 이름** | '장바구니' ↔ '카트' ↔ '담은 상품' | R-011, R-013 |
| **경어 수준** | 어떤 문구는 '~시', 어떤 문구는 없음 | R-002 |
| **표기** | `2026.08.21` ↔ `2026년 8월 21일` ↔ `8/21` | R-042 |
| **버튼 레이블 관례** | 어떤 다이얼로그는 '취소', 어떤 건 '닫기' | R-024 |

**어긋남을 찾으면 어느 쪽이 맞는지 단정하지 말고 개수를 센다.**
많은 쪽이 사실상의 제품 표준일 가능성이 높다. 다만 많은 쪽이 규칙 위반이면
그건 그것대로 보고한다 — "12개가 '취소'인데 R-024상 전부 '닫기'여야 한다"처럼.

### 3단계 · 규칙 위반을 유형별로 묶는다

문구 하나하나에 규칙 id를 붙이면 목록이 수백 줄이 되고 아무도 안 읽는다.
**같은 유형끼리 묶어서 대표 사례 두셋만 보인다.**

```
R-023 (CTA는 결과를 예고하는 동사로) · 위반 14건
  대표: "확인" (계정 삭제 다이얼로그) → "삭제하기"
        "확인" (주문 취소 다이얼로그) → "주문 취소하기"
  나머지 12건도 같은 형태 — 목록은 아래 부록에
```

### 4단계 · 우선순위를 매긴다

전부 고치라고 하면 아무것도 안 고쳐진다. **세 등급으로 나눈다.**

| 등급 | 기준 | 예 |
|---|---|---|
| **먼저** | 사용자가 잘못 행동하게 만드는 것 | 파괴적 동작 옆의 '취소'(R-024), 통하지 않는 조치 안내(R-029), 원인 모르는 재시도 권유 |
| **다음** | 이해를 막는 것 | 내부 용어 노출(R-010·R-027), 조치 없는 에러(R-026), 시스템 시점 서술(R-032) |
| **나중** | 일관성·다듬기 | 종결 혼재(R-001), 표기 흔들림(R-042), 잡초(R-016) |

**종결 혼재가 '나중'인 이유**는 덜 중요해서가 아니라 **한꺼번에 일괄로 고치는
게 효율적**이기 때문이다. 개별 수정과 성격이 다르다.

### 5단계 · 프로파일을 역추정한다 — **파일이 없을 때만**

0단계에서 프로파일 파일을 찾았으면 **역추정하지 않는다.** 대신 실제 문구가
파일의 값과 어긋나는 지점을 보고한다("파일은 해요체인데 합니다체가 7건").
어긋남을 찾는 이 모드의 성격과도 맞는다.

아래는 파일이 없을 때다. 이 모드의 숨은 산출물이다 —
실제 문구가 제품의 진짜 보이스를 말해준다.

```
역추정한 프로파일
- 종결: 해요체 (38/45가 해요체, 7개가 합니다체 — 혼재이나 다수는 해요체)
- 경어: 낮음 ('~시' 사용 3건뿐, 전부 질문형)
- 용어: 최소 (도메인 용어 노출 없음)
- 공감: 중간 (완료 문구에만 감정 표현)
- 밀도: 간결 (평균 1.2문장)
```

**추정이라고 반드시 밝히고 확인받는다.**

**그리고 파일을 만들자고 제안하는 것까지가 5단계다.** 역추정 표만 내고 끝내면
다음 세션에서 같은 일을 또 한다. 보고 형식(6단계)에 자리를 잡아 두었으니
빠뜨리지 않는다.

> 위 값으로 `voice-profile.md`를 만들어 두면 다음부터는 역추정하지 않아도 돼요.
> 서식은 `assets/voice-profile-template.md`에 있고, 프로젝트 루트나 `docs/`에
> 두면 됩니다. 만들어 드릴까요?

## 이 모드에서도 지키는 것

**SKILL.md 「상시 제약」 넷이 그대로 걸린다.** 문구 개수가 많다고 느슨해지지
않는다 — 특히 범위 경계와 규칙 id 실재가 여기서 무너지기 쉽다.

**판정 단계 중에도 걸리는 것이 있다.** 이 모드가 SKILL.md 판정층(1~5단계)의
절차를 밟지 않는다는 뜻이지, 판정 자체가 면제된다는 뜻이 아니다.

| SKILL.md | 이 모드에서는 |
|---|---|
| 0단계 프로파일 확인 | **그대로 한다** (위 0단계). 없을 때 역추정으로 대체될 뿐이다 |
| 3단계 상황 판정 | 문구마다 어느 상황인지 판정해야 규칙이 골라진다. 에러는 귀책(P-07a/b)까지 |
| 5단계 민감 상황·극소 자리 | 목록 안에 에러·파괴적 확인·버튼 레이블이 섞여 있으면 그 문구에 그대로 걸린다 |

일괄 진단에만 있는 제약은 둘이다.

- **에러 문구의 원인·조치를 모르면 고치지 않는다** (R-031). 일괄 진단에서는
  수십 개를 한꺼번에 물을 수 없으므로, **"원인·조치 확인 필요"로 분류해서
  목록으로 넘긴다.** 지어내서 고치는 것보다 낫다
- **고칠 것이 없는 문구는 목록에 넣지 않는다.** 멀쩡한 것까지 나열하면
  진짜 문제가 묻힌다

## 문구가 아주 많을 때

200개가 넘어가면 한 번에 다루기 어렵다.

1. **먼저 훑어서 어긋남만 찾는다** (2단계). 이건 전체를 봐야 보인다
2. **화면 묶음별로 나눠 자세히 본다.** 사용자에게 어느 묶음부터 볼지 물어도 된다
3. 묶음마다 위 형식으로 보고하고, 마지막에 전체 요약을 붙인다

**전부 보지 못했으면 못 봤다고 밝힌다.** 일부만 보고 "45개를 점검했습니다"라고
쓰면 그 자체가 거짓이다.
